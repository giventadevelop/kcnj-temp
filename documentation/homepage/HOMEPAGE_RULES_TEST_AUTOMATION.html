Homepage Rules — Test Automation

Companion to HOMEPAGE_OVERALL_BUSINESS_RULES.html. This page is for development databases only.

Do we already have this? No. TestSprite public tests and the MOSC / kcnj page-load suites only check that the homepage renders. They do not clone live rows, insert dummy future events, flip dates to past, seed dummy sponsors, or toggle tenant section flags per tenant. The Playwright hero checklist is a skeleton and does not seed the database.

The harness is homepage-rules-test.mjs. It copies current tenant data into marked dummy rows, changes only those dummies, verifies the SQL rules, and deletes only those dummies. Pass --tenant-id so the same script works for kcnj-prod, mosc-temp, or any other project sharing this database.

How the new harness works
  • Talks to local Docker Postgres (event_site_manager_db-postgresql-1 by default).
  • Always scopes writes with --tenant-id.
  • Clones the newest real rows for that tenant (featured events first, then others).
  • New event titles start with [HPTEST]. Sponsors and team first names use the same mark.
  • Copies one picture onto each dummy event and marks it homepage-hero (and live-image when the mode is live).
  • verify prints the SQL snapshot the homepage rules would use: upcoming count, featured upcoming vs past, live today, hero media, sponsor/team counts, section flags.
  • After you run a seed or shift, reload the homepage (or wait out the five-minute settings cache) and look at the UI.
Safety and tenant isolation
  • Delete commands only remove rows whose title, sponsor name, or team first name starts with [HPTEST].
  • Real Onam / volunteer / sponsor rows are left alone.
  • The same script is reusable: pass a different tenant for mosc-temp, mcefee-temp, or kcnj-temp if they share this database.
  • If --tenant-id is omitted, the script reads NEXT_PUBLIC_TENANT_ID from .env.local.

Parameters:

  • --tenant-id — required unless set in the environment
  • --mode / --to — future, past, or live
  • --count — how many rows to clone
  • --featured — how many of those cloned events are marked featured
  • --feature — verify slice: all, featured, upcoming, hero, live, sponsors, team, sections
  • --name — packaged scenario name
  • --events / --team / --sponsors — on or off for tenant settings

Feature scenarios vs homepage rules
Scenario name What the script does Rule to check on the homepage
upcoming-featured Deletes old dummies; clones two future events; marks one featured; turns the events section on; verifies Featured Upcoming list shows the two dummies. Featured shows the one featured future event (max 3)
no-future-past Deletes dummy events; verifies remaining real data If no real future events remain: Featured shows past featured (max 3) and the list becomes Past Events (max 6)
live-today Clones one event dated today Live Events appears (max 3)
sponsors-team Clones two sponsors and two team members; turns those sections on Team and Our Sponsors show the dummy cards (caps 6 and 8)
sections-off / sections-on Flips the three homepage display switches Upcoming / Team / Sponsors hide or return. Hero and Featured are unchanged
shift-past / shift-future Moves existing dummy events only Same dummy rows flip from Upcoming + Featured-future to Past + Featured-past, or back
all Runs upcoming-featured, sponsors-team, live-today, shift-past, shift-future, then status Global pass through the main data shapes. Clean up afterward
cleanup Deletes all [HPTEST] rows and turns the three sections back on Homepage returns to real tenant content

Individual commands (same script, one feature at a time)

  • seed-events --mode=future|past|live
  • shift-events --to=past|future|live
  • seed-sponsors / delete-sponsors
  • seed-team / delete-team
  • toggle --events=off --team=on --sponsors=off
  • verify --feature=hero (or featured, upcoming, live, sponsors, team, sections)
What you still verify in the browser

The script proves the data matches the rules. The homepage is client-rendered, so a curl of / will not show the cards. After each scenario:

  • Reload the homepage (dummy titles start with [HPTEST]).
  • If a section toggle does not change, wait out the five-minute tenant-settings cache or do a hard reload.
  • Confirm hero posters are not cropped, Featured never paginates, and empty Featured is hidden when upcoming exist but none are featured.
Not a Playwright replacement yet. Browser clicking can be added later on top of these same seed commands. The data layer is the part that was missing.
