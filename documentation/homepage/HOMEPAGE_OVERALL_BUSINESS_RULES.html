Homepage Overall Business Rules

Plain-language rules for the public homepage. These describe what visitors see, not how the code is written. Last aligned with the modernist homepage in this project.

The homepage is a stack of independent blocks. Event posters, featured cards, the calendar list, live events, the team, and sponsors each have their own rules. Some blocks are always considered (they hide themselves when empty). Others are turned on or off in Admin → Tenant Management → Settings → Homepage Display Settings.

Marking an event as featured does not automatically put it in the hero. Putting a picture in the hero does not automatically make the event featured. Turning off the events list does not hide Featured or the hero.

To test these rules with dummy data cloned from the current tenant, use Homepage Rules — Test Automation (homepage-rules-test.mjs). Pass --tenant-id so the same script works per project.

How the homepage blocks fit together
  • The hero is the large rotating poster at the top of the home page.
  • Live Events appears only when an active event is happening today (start date through end date includes today).
  • The On sale / Register now band appears only when there is at least one upcoming event.
  • Featured Events is a short spotlight strip (at most three cards). It is not a full calendar.
  • Upcoming Events is a list of up to six coming events. If there are no coming events, the same block becomes Past Events and shows up to six recent events.
  • What we do and About Us are always on the modernist homepage. They are not tenant toggles.
  • Team shows executive committee / volunteer members. It is turned on or off in tenant settings.
  • Our Sponsors shows active sponsors. It is turned on or off in tenant settings.
  • Event blocks are independent. An event can appear in the hero, Featured, Live, and the list, depending on dates and checkboxes — not because it appeared in another block.
  • Featured is not hidden just because upcoming events exist. If a coming event is marked featured, Featured still shows.
  • Past featured events appear in Featured only when there are no future events at all.
  • The Upcoming / Past list can show past events even while Featured also shows past featured cards. That is on purpose: Featured is a spotlight, the list is the recent calendar.

Editors change these under Homepage Display Settings on the tenant settings form. The site waits until those settings have loaded before showing the gated blocks, so they do not flash on and then disappear.

Cache note: Tenant settings are remembered in the browser for about five minutes. After you flip a switch in admin, reload the homepage, or wait for that cache to expire, to see the change. A hard refresh is enough; you do not need to wait for the 30-minute listing refresh.

Site-type starting points (when a new tenant is created)

  • Event organization — events and sponsors on; team off.
  • Sports — same as event organization, plus the team / squad switch on.
  • Church — executive team on; sponsors off.
  • Personal profile — events, team, and sponsors off; profile sections (writings, achievements, family, and so on) on.
  • Hybrid — profile sections plus events and sponsors on.
  • Gas station / dashboard — public homepage sections off.
  • These are only starting values. An admin can still flip each switch later.
Hero rotation rules

The hero shows pictures, then slowly moves to the next picture. Visitors can also pause or step through the pictures.

Which event pictures can appear

  • The picture must be marked as a homepage hero picture or a hero picture.
  • If the picture has a “start showing from” date, that date must be today or earlier. A future show-from date keeps the picture hidden.
  • The event attached to the picture must still be coming up or still going (its end date is today or later). Past events do not rotate in the hero.
  • For a repeating event, the hero uses the next occurrence. If there is no next date, that event is skipped.
  • A picture with no event attached is not used as an event slide.
  • If the tenant setting “show event hero images” is turned off, event pictures are skipped and the hero uses tenant default pictures (or the emergency fallback).
  • An event that is marked inactive can still appear in the hero if an admin explicitly marked its picture as hero / homepage hero. That is an opt-in for the slider, not for the event list.

Tenant default pictures and fallback

  • After event pictures, the site can add the tenant’s default hero pictures (uploaded in tenant settings), if “include default pictures with event pictures” is on (this is on by default).
  • Only active default pictures are used.
  • How many defaults appear depends on the tenant’s display mode:
    • Slideshow — use the active defaults, up to the max display count.
    • Random — pick a few active defaults at random.
    • Single — use one active default.
  • If there is at least one event picture but the combined slideshow would be only one picture, the site adds the emergency default picture so the hero can still rotate (event picture, then default).
  • If there are no event pictures, the hero uses tenant defaults only.
  • If there are no event pictures and no tenant defaults, the hero shows the bundled emergency picture so the top of the page is never blank.

How rotation behaves

  • Each picture stays on screen for the seconds set on that media row. If none is set, it stays for 8 seconds.
  • Pictures change with a smooth crossfade. The current picture is not cropped to fill the frame; the whole poster stays visible.
  • If there are two or more pictures, Previous, Next, and Pause / Play appear on hover (desktop) or tap (phone). On a phone the controls hide again after a few seconds.
  • Pause stops the automatic change. Play starts it again from the picture you are on.
  • If a later refresh finds the same set of pictures, the current picture keeps rotating. The slider does not jump back to the first picture.

Buy Tickets / Register overlay on the hero

  • The overlay appears only for an upcoming event (today or a future start date).
  • Ticketed events (including Event Cube, an outside ticket link, or a ticketed fundraiser) show a Buy Tickets overlay. A ticketed fundraiser uses the fundraiser artwork.
  • If the event is not ticketed but requires registration, the overlay is Register Here.
  • Past events and events with no ticket or registration path get no overlay.
  • The overlay sits on the poster corner. It stays readable even when the poster panel is wider than the picture.
Tip: Hero membership is a picture checkbox (homepage hero / hero). Featured membership is an event checkbox. They are not the same switch.
Featured Events rules

Featured is a short spotlight. It never paginates. Visitors either see up to three cards, or they see no Featured strip at all.

What makes an event featured

  • The event itself must have the Featured Event checkbox turned on.
  • A featured picture is preferred, but the card can still show if another usable picture exists (see image order below).
  • Priority ranking is a number. Lower number means higher place (1 appears before 10).

Which featured events show on the homepage

  • First the site asks: are there any upcoming events at all (active events whose start date is today or later, within about a year)?
  • If yes, there are upcoming events:
    • Featured shows only upcoming featured events.
    • Past featured events are hidden, even if they are still marked featured.
    • If none of the upcoming events are marked featured, the Featured strip is hidden.
    • Upcoming featured cards are ordered by priority (lowest number first), then by start date (soonest first).
  • If no, there are no upcoming events:
    • Featured shows past featured events only.
    • They are ordered newest first (latest end date, or start date if there is no end date).
  • In both cases the hard cap is 3 cards. There is no “next page” on Featured.

Which picture each featured card uses

  • Prefer a picture marked featured event image.
  • If none, use a homepage hero, hero, or flyer picture.
  • If none of those, use any picture that still has a working image address.
  • If a picture has a “start showing from” date in the future, it is skipped until that date.
  • If the preferred address has expired, the site tries a stable file address, then a thumbnail.
Common mix-up: Having upcoming events does not hide Featured. Featured hides only when upcoming events exist and none of those upcoming events are marked featured.
Featured is not turned off by the “Show Events Section” tenant switch. That switch only hides the Upcoming / Past list.
Live Events and the On sale / Register band

These sit under the hero. They have no on/off switch in tenant settings. They hide themselves when there is nothing to show.

Live Events

  • An event is “live today” when it is active, it has a start date, and today falls on or between the start date and the end date (if there is no end date, the start date is used as the end date too).
  • At most three live events are shown.
  • The preferred picture is one marked as a live event image. If that is missing, any picture on the event is used.
  • If nothing is live today, the Live Events block is not shown at all (no empty heading).
  • A Live badge sits on the picture. “All events” goes to the calendar page.

On sale / Register now band

  • This band is shown only when there is at least one upcoming event. Past events never appear here.
  • Which event is picked, in order:
    • An upcoming featured event that is ticketed
    • Any upcoming featured event
    • The first upcoming ticketed event
    • The first upcoming event
  • If that event is ticketed, the heading is On sale now and the button is Get tickets.
  • If it is not ticketed but has a registration link, the heading is Register now and the button is Register (opens an outside site when the registration is external).
  • Otherwise the button is View event.
Upcoming and Past Events rules

This is the homepage card list under Featured. On the modernist home it is titled Upcoming Events or Past Events. It shows at most six cards.

When the section appears

  • The tenant setting “show events section on the home page” must be on. It is on by default.
  • If that setting is off, the list is hidden. The hero and Featured are not affected by this setting.

Upcoming Events (the normal case)

  • Only active events are considered.
  • An upcoming event has a start date of today or later.
  • They are shown soonest first.
  • The site may fetch more than six (it asks for 15) so repeating events can be grouped. After grouping, visitors see at most six.
  • A repeating series shows one card: the next occurrence. Later repeats from the same series are not listed separately.
  • If the next occurrence is more than one year away, or there is no next date, that series is skipped.
  • Child rows that belong to a series but are not the series itself are skipped.
  • Buy Tickets, Register, and Donate actions appear on upcoming cards when the event supports them.

Past Events (only when there are no upcoming events)

  • If the upcoming list is empty after grouping, the same section switches to Past Events.
  • Past means the event’s end date is before today (or the start date, if there is no end date).
  • They are shown newest first.
  • Visitors still see at most six.
  • Each card gets a Past Event badge.
  • Ticket and register buttons are hidden on past cards.
  • This past fallback is on for the homepage. If it were turned off, the section would stay empty instead of showing history.

Empty and “see more” behavior

  • If there are no upcoming events and no past events, the section explains that events are temporarily unavailable or empty. It does not invent cards.
  • If more than six events exist after grouping, visitors get a path to the full calendar (View calendar / See more events) at /events.
  • The homepage list never paginates inside the section. Six is the cap; the rest live on the Events page.
Team (executive committee) rules

The homepage Team block is the executive committee / volunteer list. Turn it on or off in tenant settings with Show Team Members Section.

How it is enabled and disabled

  • The switch lives under Admin → Tenant Management → Settings → Homepage Display Settings → Show Team Members Section.
  • When the switch is on, the homepage fetches team members and shows the Team block (after settings have finished loading).
  • When the switch is off, the Team block is not rendered and the site does not call the team API.
  • If tenant settings cannot be loaded, Team stays on so the page does not go blank for a missing setting.
  • The header About menu adds a Team link to the full team page only when this switch is on (and only on event / church style sites, not personal-profile navigation).

Who appears on the homepage

  • People come from the executive committee / team members list (Admin → Executive Committee), not from the event calendar.
  • Only members marked Active are listed.
  • They are ordered by priority order, lowest number first (0 appears before 10). That is rank, not a date.
  • The homepage shows at most six people. The rest belong on the full Team page.
  • If the switch is on but nobody is active, visitors still see the Team heading and the line “Team members will appear here when available.”

What each card shows

  • Photo from the member’s profile image. If there is no photo, a plain placeholder is used.
  • Name is first name plus last name. If those are empty, the member title is used.
  • Role line is designation, or title if designation is empty.
  • Short text is expertise if present, otherwise bio.
Sponsors rules

The homepage sponsor strip is turned on or off with Show Sponsors Section. It is a thank-you strip, not the full sponsors directory.

How it is enabled and disabled

  • The switch lives under Admin → Tenant Management → Settings → Homepage Display Settings → Show Sponsors Section.
  • When on, the homepage fetches sponsors after settings have loaded and shows Our Sponsors.
  • When off, the homepage strip is hidden and sponsor data is not fetched.
  • If tenant settings cannot be loaded, sponsors stay on.
  • The header About menu still offers a Sponsors link to the sponsors page on event-style sites, even if the homepage strip is off. Turning off the homepage strip does not hide that menu item.

Who appears on the homepage

  • Sponsors come from the event sponsors list (Admin → Event Sponsors).
  • Only sponsors marked Active are listed.
  • They are ordered by priority ranking, lowest number first.
  • The site may fetch up to 12 and then shows at most eight on the homepage.
  • If the switch is on but there are no active sponsors, visitors still see the heading and “Sponsors will appear here when available.”
  • See all sponsors goes to the full sponsors page.

What each card shows

  • Picture order: a sponsor banner picture if one exists, then a hero picture, then a logo, then a generic placeholder.
  • The sponsor type (if set) appears as a badge and as a small label.
  • The main title is company name, or the sponsor name if there is no company name.
  • If both a person name and a company name exist, the person name is shown as a secondary line.
  • A website button appears when a website address is stored.
Always-on About and What we do
  • What we do is always on this homepage. It is not a tenant toggle.
  • About Us is always on this homepage. It is not a tenant toggle.
  • About copy on this site is the organization story (mission, legal name, phone, email). It does not come from the event list.
  • Hiding Team or Sponsors does not hide About Us.
Header menu (not the homepage body)

The top navigation is a separate set of tenant switches under Header Menu. Turning a header item off hides it from the menu. It does not, by itself, hide the matching homepage block.

  • These default on: Home, About, Events, Features, Calendar, Gallery, Contact.
  • These default off: News, Downloads, Links, Services, Achievements, Affiliations, Projects, Family.
  • The extra items reuse content from Admin → Profile Site when the tenant is a profile or hybrid site.
  • On event / church style sites, the About dropdown includes About Us, Team (only if the Team homepage switch is on), and Sponsors.
Related rules on the Events calendar page

The Events page is the full calendar. It is not the homepage strip, but visitors land there from “View calendar.”

  • Visitors can switch between future and past events.
  • If they are looking at future events and none exist, the page says: No future events created yet. Please check back later, and still points them at the future / past switch.
  • The page can silently pick up new events in the background (see silent refresh below) without a full reload.
Silent refresh (no full page reload)
  • While the homepage or Events page stays open, the site refreshes listings about every 30 minutes.
  • Existing cards stay on screen. There is no flash of a loading spinner that wipes the page.
  • If the browser tab is hidden, the refresh waits. When the visitor comes back, it refreshes if 30 minutes have passed.
  • Using the browser Back button into a cached page also triggers a refresh when needed.
  • If the quiet refresh fails, the current cards stay. The page does not go blank.
  • This applies to the hero pictures, Featured, Upcoming / Past, Team, Sponsors, and the Events calendar list.
  • A normal reload still shows the latest data immediately. You do not have to wait 30 minutes after adding a test event.

Admin switches that control this (plain names):

  • Featured Event on the event — required for the Featured strip.
  • Featured priority — lower number shows first among upcoming featured events.
  • Homepage hero / Hero image on a picture — required for that picture to enter the hero rotation.
  • Featured event image on a picture — preferred picture for a Featured card.
  • Start showing from on a picture — hides the picture until that date.
  • Hero display seconds — how long that hero picture stays before the next one.
  • Active on the event — required for Upcoming / Past cards. Hero can still show an inactive event if its picture is hero-flagged.
  • Show Events Section (tenant setting) — shows or hides the Upcoming / Past list only. Does not hide Featured, Live, or the hero.
  • Show Team Members Section (tenant setting) — shows or hides the homepage Team block and the header Team link.
  • Show Sponsors Section (tenant setting) — shows or hides the homepage Our Sponsors strip. The header Sponsors link still appears on event-style sites.
  • Show event hero images (tenant setting) — allows or blocks event pictures in the hero.
  • Include default hero pictures with events — whether tenant defaults follow event slides.
  • Default hero display mode — slideshow, random, or single for tenant defaults.
  • Active on a team member — required for that person to appear in Team.
  • Priority order on a team member — lower number appears first.
  • Active on a sponsor — required for that sponsor to appear in Our Sponsors.
  • Priority ranking on a sponsor — lower number appears first.
  • Live event image on a picture — preferred picture for the Live Events block.
  • Header Menu switches — Home, About, Events, and the rest control the top navigation only, not the homepage body.
  • Enable Membership Subscription sits next to the homepage display switches but does not show or hide a homepage events block.
