Profile Audience CRM v2 — Index

Version: 2.0  |  Date: July 2026  |  Status: Implemented (Loops 6–9)
Parent: Personal Profile Site PRD  |  Loops: Iterative loops 6–9

Personal-profile tenants can capture, import, and bulk email an audience scoped to their public_profile. Data lives in a single table profile_audience_contact — separate from tenant-wide user_profile.is_email_subscribed members.

Admin UI: /admin/profile-site → Audience tab in both mosc-temp and event-site-manager. Public capture: mosc-temp only.

Entity, Liquibase, send-to-profile-audience.

Batch jobs PRD

RecipientType.PROFILE_AUDIENCE in email batch.

Plain-text PRD

For node scripts/dev.js parse-prd.

Goals

  • Capture emails from subscribe form, contact form (when enabled), CSV import, and admin manual entry
  • Send newsletter/promotion templates to opted-in profile audience only
  • Per-contact unsubscribe token — never merge with member subscription flags

Compliance

  • Include unsubscribe link (token per contact) in every profile-audience bulk email
  • Never email rows with opt_in_status = OPTED_OUT
  • CSV import: validate email; upsert on (tenant_id, email)
  • Send requires tenant admin (existing layout admin check)

Out of scope (v2.0)

  • Named contact lists (profile_contact_list)
  • Double opt-in confirmation email
  • Merging with user_profile subscribers
  • WhatsApp bulk to profile audience

Build script: scripts/build-profile-audience-v2.ps1 — compiles service → batch-jobs → lint both frontends.
