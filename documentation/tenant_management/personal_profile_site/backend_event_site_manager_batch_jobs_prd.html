2. Why only two entities change in batch-jobs

The batch application embeds a small copy of domain entities (typically ~11 tables) for jobs that send email, process payments, etc. Those jobs load TenantSettings (logo, support email, branding) and may reference TenantOrganization.

New profile tables exist in PostgreSQL but are invisible to Hibernate until you add matching @Entity classes. Hibernate ddl-auto: validate only validates mapped entities — not every table in the database.

Therefore: Add columns only to entities batch-jobs already maps. Do not add PublicProfile entities to batch-jobs unless a future job needs them.
