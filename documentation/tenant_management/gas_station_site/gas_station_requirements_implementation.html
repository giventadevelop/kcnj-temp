Gas Station COO & Tenant Site Types — Requirements & Implementation Record

Version 1.0 · 2026-07-04 · Repos: mosc-temp (satellite frontend), event-site-manager (platform admin), kluvo-ai-service (Spring Boot backend)

1. Business requirement

Integrate the AI Gas Station COO concept (blueprint at E:\Categories\Categories\Software_Projects\Gas_Station_AI) into the multi-tenant event-site platform: each gas-station client (single owner or chain) is onboarded as a tenant; client management, subscription billing, and the daily-brief dashboard live in this platform, while the AI/LLM engine is a separately deployed service that writes curated results back via the tenant-scoped REST API. Additionally, complete the pending personal-profile site type integration.

3. Multi-location (chain) requirements

  • One tenant = one paying customer owning 1..N gas_station_location rows (own id, code unique per tenant, full address, geo lat/long, region label, timezone, capability flags).
  • Chain-level recommendations: gas_station_recommendation.station_id is nullable — NULL = cross-store item.
  • Rollups are computed (SUM/GROUP BY), never stored; dashboards offer an "All stations" view plus per-station scope; a Compare view ranks stores.

5.3 Satellite frontend (mosc-temp — one tenant per deployment)

  • Types (profileSite.ts, gasStation.ts, DTO fields), presets lib, 9 proxy route pairs.
  • Tenant-management: Site Type dropdown (auto-applies presets on change), profile section toggles, Gas Station AI Engine panel.
  • /admin/gas-station: daily brief dashboard (date + station switcher, All-stations rollup, chain-level recs first, Accept/Dismiss/Done + owner feedback), Stations CRUD, Integrations registry, Compare, Billing (§5.5).
  • /admin/profile-site + public ProfileHomeSections gated by settings flags; admin hub tiles for both modules.
  • Demo seed: tenant demo_gas_station_001 (3 stations, 7 days of metrics, 6-item morning brief incl. 2 chain-level).

5.4 Platform admin (event-site-manager — all tenants, tenant passed on demand)

  • Same types/presets/proxies; Site Type on org form; preset action takes an explicit tenantId (never env).
  • /admin/gas-station and /admin/profile-site pages driven by the ?tenant= selector; with no tenant selected they show a site-type tenant picker (all tenants whose site type matches the module, Select → scopes the page).
  • Admin dashboard + navigation buttons: Personal Profile, Gas Stations.

5.5 Billing dashboard (/admin/gas-station/billing in mosc-temp)

  • Current plan summary; graduated pricing tier cards; per-location Included toggles with live monthly-total preview (src/lib/gasStationPricing.ts).
  • Actions via /api/stripe/gas-station-billing: checkout (Stripe Checkout, mode subscription, quantity = billable count), portal (Customer Portal), sync-quantity (prorated update). Auto-creates the tenant's Stripe customer.
  • Go-live setup: create graduated Price in Stripe; env STRIPE_GAS_STATION_PRICE_ID, STRIPE_GAS_ENABLE_ACH=true; enable ACH + Customer Portal in Stripe settings.
